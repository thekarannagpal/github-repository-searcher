What the assignment asked for

Requirements at a glance

1. Search GitHub

Query by repository name, language and sort key (stars / forks / updated).

2. Persist results

Store repository details and statistics in PostgreSQL; update existing rows, never duplicate.

3. Retrieve stored results

Filter by language, minimum stars and sort order through a second REST endpoint.

4. Robustness

Handle invalid responses, rate limits and empty results. No UI; Postman-testable.

Architecture

Clean, layered design

Client (Postman / Swagger)
        │
        ▼
GithubController ──────► validation + DTO mapping
        │
        ├──► GithubSearchService ──► GithubApiClient ──► api.github.com
        │                              │
        │                              └──► Rate-limit / error translation
        │
        └──► RepositoryService ──────► RepositoryRepository (JPA)
                                         │
                                         ▼
                                     PostgreSQL

Dedicated mapper and DTOs keep GitHub's snake_case payload out of the API response and the database entity.

Upsert behaviour

Repeated searches stay clean

The GitHub repository id is the database primary key.

  • First search → new row inserted.
  • Same search again → existing row updated with fresh stars/forks/timestamps.
  • No duplicates, so the stored dataset always reflects GitHub's latest data.
repositoryRepository.saveAll(entities);  // JPA upsert by id
7 / 11
Endpoint 2 · live

Retrieve stored results

GET /api/github/repositories?language=Java&minStars=100&sort=stars

  • language — case-insensitive filter
  • minStars — minimum star count
  • sort — stars, forks or updated (descending, default stars)

Implemented with JPA Specifications; sort keys are whitelisted through an enum.

8 / 11
Edge cases

Errors are handled explicitly

400 Bad Request

Blank query, invalid sort, negative minStars, malformed JSON — with field-level messages.

429 Too Many Requests

GitHub rate-limit headers are translated into 429 plus Retry-After.

502 Bad Gateway

GitHub unreachable, timeout, or non-success status from the upstream API.

200 + empty list

No matches is a valid result, not an error; nothing is written to the database.
